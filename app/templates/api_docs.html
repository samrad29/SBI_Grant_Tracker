SBI Grant Tracker API docs

Reference for frontend integration. Most JSON routes use GET; /api/opportunities/semantic-search and /api/auth/login also accept POST; /api/db_migration/reset_tables accepts GET or POST.

Database selection follows get_db_connection(test_mode=is_test_mode()): set DATABASE_URL for Postgres, or use local SQLite when unset. TEST_MODE controls test DB behavior when not using DATABASE_URL.

User activity routes read session["user_id"]. The client must establish a Flask session with that key before calling them; they do not take user_id as a query parameter.

For mutating actions (bookmarks, checklist, project tasks), the handlers still use GET with query parameters.

Sessions: Login and net-ID validation set a permanent signed cookie. Idle timeout defaults to 40 minutes (SESSION_LIFETIME_MINUTES env); each request extends the window. Cross-origin SPAs should send credentials: "include" and may need SESSION_CROSS_SITE_COOKIES=1 on the API host.

Authentication (`auth.py`)

Two flows share the same Flask session cookie:

  • Client portal login — POST /api/auth/login → session["user_id"].
  • Group registration — GET /api/auth/validate_netID → session["group_id"] and session["group_name"], then GET /api/auth/create_user to add a user to that group.
GET/api/auth/validate_netID

Checks groups.net_id. On success, starts a permanent session with the group context (used before the create-user page).

Query params
  • netID (required): group net ID from the groups table
Example response (200)
{
  "message": "NetID validated successfully",
  "group_name": "Example Tribe",
  "group_id": "1"
}

400: { "message": "NetID required" } · 404: { "message": "NetID not found" }

GET/api/auth/group_session

Returns the group name from the registration session (after net-ID validation). Use to gate the create-user UI.

Example response (200)
{ "group_name": "Example Tribe" }

401: { "message": "Not authenticated" } (no group_name in session)

GET/api/auth/create_user

Creates a row in users for the group validated in the current session. Password is stored as a Werkzeug hash. role is set to default on insert; the next numeric id is assigned from MAX(id) + 1 on the users table.

Query params
  • user_name (required): display name stored in users.user_name
  • email (required)
  • password (required)
  • password_confirmation (required; must match password)
Session

Requires session["group_id"] from /api/auth/validate_netID. Stored on the new user as users.group_id.

Duplicate check

Rejects if a user already exists with the same user_email and group_id.

Example response (200)
{ "message": "User created successfully" }

400: Name required · Email and password required · Passwords do not match · Invalid email · Invalid password · User already exists

401: { "message": "Group ID not validated, session invalid" }

500: { "message": "Error creating user: …" }

Grant status values

Opportunity list endpoints only return grants where grants.status is posted or forecasted (open listings from Grants.gov normalization).

  • posted / forecasted — active synopsis or forecast from ingestion.
  • closed — application deadline has passed. Set by the offline script python -m scripts.check_past_deadlines (Groq interprets deadline fields). Daily ingestion refreshes other columns but does not overwrite closed back to posted/forecasted for the same opportunity_id.
  • archived — not seen on the Grants.gov search feed for several days (pipeline archive step). Excluded from list endpoints like closed.

Detail view /api/opportunities/<id> returns any row in grants, including closed or archived, if you still have the id.

Public link (`grant_gov_url`)

List and detail responses include grant_gov_url: the best public “more information” link for the opportunity, computed at ingestion (and backfill) by compute_grant_public_url in pipelines/gran_gov/ingestion_utils.py.

  • If Grants.gov provides a funding description link (link_url on the synopsis), that URL is stored.
  • If no such link exists, grant_gov_url is null in JSON (SQL NULL in the database). The UI should treat missing links as “no public URL available,” not as a broken Grants.gov detail page.

Related column link_url on the full detail payload is the raw funding-description link from the API (also may be null).

Core data endpoints (`api.py`)

GET/api/opportunities

Lists tribal-eligible, open opportunities (status in posted, forecasted). Used by the grants dashboard. Response fields are stable; tribal scores are not included in JSON (use /api/get_opportunities_v2 for score fields).

Filters (all modes)
  • Requires tribal_eligibility.is_tribal_eligible = true.
  • grants.status IN ('posted', 'forecasted') — closed and archived grants are omitted.
Query params
  • tags (optional): comma-separated tags, example Housing,Energy. Matching is case-insensitive against grant_tags.tag.
  • q (optional): substring match on title or agency (Postgres ILIKE), example tribal health
Precedence
  • If tags is non-empty, tag mode is used (even if q is also present).
  • Else if q is non-empty, search mode is used.
  • Else: default list.
Sorting (order only — scores not returned)
  • tags: ordered by matching grant_tags total_score descending.
  • Default and q: ordered in SQL by COALESCE(relevancy_score,0) + COALESCE(freshness_score,0) descending (tribal rank from tribal_eligibility, not exposed in the payload).
Limits
  • Default: up to 100 rows from SQL, then capped to 150 in the handler.
  • q: no SQL LIMIT; handler returns at most 150 rows.
Response shape
  • Default and q: opportunity_id, title, description, agency, status, posted_date, estimated_funding, grant_gov_url — no relevancy_score or freshness_score.
  • tags: one object per opportunity (aggregated in Python): opportunity_id, title, agency, status, estimated_funding, grant_gov_url, total_score, tag_scores (no description or tribal score fields).
Example response (`tags=Housing,Energy`)
[
  {
    "opportunity_id": "336489",
    "title": "Community Learning Grant",
    "agency": "Department of Education",
    "status": "posted",
    "estimated_funding": 250000.0,
    "grant_gov_url": "https://www.grants.gov/.../funding-description-link",
    "total_score": 18.0,
    "tag_scores": [
      { "tag": "Housing", "tag_score": 10.0 },
      { "tag": "Energy", "tag_score": 8.0 }
    ]
  }
]
Example response (default or q=health)
[
  {
    "opportunity_id": "336489",
    "title": "Community Learning Grant",
    "description": "Funding for local education initiatives.",
    "agency": "Department of Education",
    "status": "forecasted",
    "posted_date": "2026-03-10",
    "estimated_funding": 250000.0,

GET/api/get_opportunities_v2

Client portal list endpoint. Same open/tribal-eligible filters as v1, but returns relevancy_score and freshness_score and uses them in tag-mode sorting as well.

Tribal scoring (`tribal_eligibility`)
  • relevancy_score — keyword/agency/eligibility content score (updated on new grants and when grant content changes during daily ingestion).
  • freshness_score — 0–15 from posted_date age (recomputed daily for all rows with tribal eligibility).
  • Rank used for sorting = relevancy_score + freshness_score (nulls treated as 0). The portal displays this sum in the “Tribal relevancy” column.
Query params
  • tags (optional): comma-separated tags (same matching as v1).
  • q (optional): title/agency ILIKE search.
Precedence & sorting
  • tags present → tag mode: sort by sum(matching tag scores) + relevancy_score + freshness_score descending. Response includes total_score, tag_scores, relevancy_score, freshness_score.
  • q present (no tags) → up to 50 matches, sorted by tribal rank descending.
  • Neither → up to 100 rows from SQL, sorted by tribal rank descending (no secondary posted-date re-sort).

    "estimated_funding": 250000.0,
    "grant_gov_url": "https://www.grants.gov/...",
    "relevancy_score": 45.0,
    "freshness_score": 15.0
  }
]
Example response (tags=Housing,Energy)
[

GETPOST/api/opportunities/semantic-search

Natural-language search over tribally eligible, open grants using vector embeddings from the grants_ai table. The query is embedded with OpenAI; results are ranked by cosine similarity to each grant’s stored embedding.

Use this for free-text queries (for example “funding to replace lead pipes on tribal land”). For tag filters or title/agency substring search, use /api/opportunities or /api/get_opportunities_v2 instead. The client portal prioritizes semantic search when its semantic field is filled.

Requirements
  • Postgres only — requires DATABASE_URL, the pgvector extension, and populated grants_ai.embedding rows (from the ingestion pipeline or python -m scripts.extract_embed).
  • OpenAI — OPENAI_API_KEY is used to embed the user query at request time (EMBEDDING_MODEL, default text-embedding-3-small).
  • No Flask session required (public JSON route).
Filters (always applied)
  • tribal_eligibility.is_tribal_eligible = true
  • grants.status IN ('posted', 'forecasted') — closed and archived are omitted.
  • grants_ai.embedding IS NOT NULL — grants without extraction/embedding do not appear.
Query params (GET)
  • q or query (required): natural-language search string.
  • limit (optional): max results, default 50, max 150.
Request body (POST, JSON)
  • q or query (required): same as GET.
  • limit (optional): same as GET.
Sorting

Ordered by similarity_score descending (cosine similarity between query embedding and grant embedding; higher is more similar).

Response shape

JSON array of objects:

  • opportunity_id, title, description, agency, status, posted_date, estimated_funding, grant_gov_url
  • purpose — AI-extracted summary from grants_ai
  • relevancy_score, freshness_score — from tribal_eligibility (may be null)
  • similarity_score — float 0–1 (rounded to 6 decimal places in the API response)
Example request (GET)
GET /api/opportunities/semantic-search?q=broadband%20for%20rural%20tribal%20communities&limit=25
Example request (POST)
POST /api/opportunities/semantic-search
Content-Type: application/json

{ "q": "solar grants for tribal housing", "limit": 25 }
Example response (200)
[
  {
    "opportunity_id": "336489",
    "title": "Tribal Broadband Connectivity Program",
    "description": "Funding to expand high-speed internet access…",
    "agency": "NTIA",
    "status": "posted",
    "posted_date": "2026-03-10",
    "estimated_funding": 500000.0,

GET/api/opportunities/total_funding

Aggregated SUM(estimated_funding) and grant counts from grants. Does not apply the tribal-eligibility or open-status filters used on /api/opportunities.

Query params
  • tag (optional): comma-separated tags. When provided, only grants with matching grant_tags rows (case-insensitive) and positive per-opportunity tag score totals are included; grouped by tag.
Response shape
  • Without tag: array of agency, total_funding, total_grants, ordered by total_funding descending.
  • With tag: array of tag, total_funding, total_grants, ordered by total_funding descending.

Maintenance / data reset

GET / POST/api/db_migration/add_unbookmarked_grants

Idempotent schema tweak: adds unbookmarked on user_grant_activity if missing.

GET / POST/api/db_migration/normalize_grant_dates

Re-parses date strings already stored on grants (no Grants.gov API call). Use only when the raw text is still in the database. If a previous run set dates to null, use /api/db_migration/refetch_grant_dates instead.

Response
{ "message": "Grant dates normalized to YYYY-MM-DD where parseable", "rows_updated": 0, "rows_total": 0 }
GET / POST/api/db_migration/refetch_grant_dates

Calls Grants.gov fetchOpportunity for each row in grants, reads postingDate (e.g. Nov 13, 2023 12:00:00 AM EST), and writes ISO YYYY-MM-DD to posted_date, close_date, deadline_date, last_updated_date. Use to recover after dates were nulled by a bad normalize pass.

Query params
  • limit (optional): max grants to process
  • delay (optional): seconds between API calls (default 0.25)
Response
{
  "message": "Refetched grant dates from Grants.gov API",
  "rows_total": 0,
  "api_ok": 0,
  "api_errors": 0,
  "posted_date_set": 0,
  "posted_date_still_null": 0
}
GET / POST/api/db_migration/update_grant_gov_url

Backfills grants.grant_gov_url for every row using compute_grant_public_url: copies the funding description link_url when present; otherwise sets grant_gov_url to null (same as ingestion).

Response
{ "message": "grant_gov_url refreshed …", "rows_updated": 0 }
GET / POST/api/db_migration/add_relevancy_score

Idempotent schema tweak: adds relevancy_score and freshness_score on tribal_eligibility if missing. Backfills both columns for every grant joined to tribal eligibility. Safe to run once on an existing database before the daily job has populated scores.

Response
{
  "message": "Tribal scoring updated on existing tribal_eligibility rows",
  "rows_scored": 0,
  "rows_updated": 0,
  "rows_skipped": 0,
  "freshness_refreshed": 0
}
GET / POST/api/db_migration/reset_tables

Destructive. Drops all tables in the public schema (Postgres) or all user tables (SQLite). Use only in dev or with a full backup.

Response

{ "message": "Tables reset successfully (N dropped)" } on success.
