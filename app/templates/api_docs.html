SBI Grant Tracker API docs

Reference for frontend integration. Most JSON routes use GET; /api/db_migration/reset_tables also accepts POST.

Database selection follows get_db_connection(test_mode=is_test_mode()): set DATABASE_URL for Postgres, or use local SQLite when unset. TEST_MODE controls test DB behavior when not using DATABASE_URL.

User activity routes read session["user_id"]. The client must establish a Flask session with that key before calling them; they do not take user_id as a query parameter.

For mutating actions (bookmarks, checklist, project tasks), the handlers still use GET with query parameters.

Authentication (`auth.py`)

POST/api/auth/login

Validates email/password against users and sets session["user_id"] (signed cookie; requires SECRET_KEY in production).

Request body (JSON)
  • email (required)
  • password (required)
Example response (200)
{ "message": "User logged in successfully", "user_id": "demo-user" }

401: { "message": "Invalid email or password" }

GET/api/auth/session

Returns the current session user id.

Example response (200)
{ "user_id": "demo-user" }

401: { "message": "Not authenticated" }

POST/api/auth/logout

Clears session["user_id"].

Example response (200)
{ "message": "User logged out successfully" }

Grant status values

Opportunity list endpoints only return grants where grants.status is posted or forecasted (open listings from Grants.gov normalization).

  • posted / forecasted — active synopsis or forecast from ingestion.
  • closed — application deadline has passed. Set by the offline script python -m scripts.check_past_deadlines (Groq interprets deadline fields). Daily ingestion refreshes other columns but does not overwrite closed back to posted/forecasted for the same opportunity_id.
  • archived — not seen on the Grants.gov search feed for several days (pipeline archive step). Excluded from /api/opportunities like closed.

Detail view /api/opportunities/<id> returns any row in grants, including closed or archived, if you still have the id.

Public link (`grant_gov_url`)

List and detail responses include grant_gov_url: the best public “more information” link for the opportunity, computed at ingestion (and backfill) by compute_grant_public_url in pipelines/gran_gov/ingestion_utils.py.

  • If Grants.gov provides a funding description link (link_url on the synopsis), that URL is stored.
  • If no such link exists, grant_gov_url is null in JSON (SQL NULL in the database). The UI should treat missing links as “no public URL available,” not as a broken Grants.gov detail page.

Related column link_url on the full detail payload is the raw funding-description link from the API (also may be null).

Core data endpoints (`api.py`)

GET/api/opportunities

Lists tribal-eligible, open opportunities (status in posted, forecasted). Supports tag search, text search, or a default list (up to 50 rows).

Filters (all modes)
  • Inner join tribal_eligibility with is_tribal_eligible = true.
  • grants.status IN ('posted', 'forecasted') — closed and archived grants are omitted.
Query params
  • tags (optional): comma-separated tags, example Housing,Energy. Matching is case-insensitive against grant_tags.tag.
  • q (optional): substring match on title or agency (Postgres ILIKE), example tribal health
Precedence
  • If tags is non-empty, tag mode is used (even if q is also present).
  • Else if q is non-empty, search mode is used.
  • Else: default list (up to 50), ordered by database default.
Response shape
  • Default and q: includes posted_date (ISO YYYY-MM-DD after ingestion or backfill). Sorted by true calendar date (newest first), not alphabetical month names—legacy values like September 15, 2024 are parsed in the API until you run /api/db_migration/normalize_grant_dates.
  • tags: one object per opportunity (aggregated in Python), ordered by total_score descending. Includes the same grant fields plus total_score and tag_scores (array of { "tag", "tag_score" }). Only tags with positive scores for that opportunity are included.
Example response (`tags=Housing,Energy`)
[
  {
    "opportunity_id": "336489",
    "title": "Community Learning Grant",
    "agency": "Department of Education",
    "status": "posted",
    "estimated_funding": 250000.0,
    "grant_gov_url": "https://www.grants.gov/.../funding-description-link",
    "total_score": 18.0,
    "tag_scores": [
      { "tag": "Housing", "tag_score": 10.0 },
      { "tag": "Energy", "tag_score": 8.0 }
    ]
  }
]
Example response (default or q=health)
[
  {
    "opportunity_id": "336489",
    "title": "Community Learning Grant",
    "description": "Funding for local education initiatives.",
    "agency": "Department of Education",
    "status": "forecasted",
    "estimated_funding": 250000.0,
    "grant_gov_url": null
  }
]

GET/api/opportunities/total_funding

Aggregated SUM(estimated_funding) and grant counts from grants. Does not apply the tribal-eligibility or open-status filters used on /api/opportunities.

Query params
  • tag (optional): comma-separated tags. When provided, only grants with matching grant_tags rows (case-insensitive) and positive per-opportunity tag score totals are included; grouped by tag.
Response shape
  • Without tag: array of agency, total_funding, total_grants, ordered by total_funding descending.
  • With tag: array of tag, total_funding, total_grants, ordered by total_funding descending.
Example response (no tag)
[
  { "agency": "Department of Education", "total_funding": 1200000.0, "total_grants": 42 }
]

User activity endpoints (`user_activity.py`)

All routes in this section require session["user_id"] to be set. Missing session keys will surface as a server error.

GET/api/user_activity/update_user_grant_status

Creates or updates a user's status for a grant in user_grant_activity.

Query params
  • opportunity_id (required): grant id
  • status (required): arbitrary status string (for example viewed, saved, applied)
Example response
{ "message": "Grant marked successfully" }
GET/api/user_activity/bookmark_grant

Bookmarks a grant for the session user: upserts user_grant_activity with status = 'saved' and is_bookmarked = TRUE (on conflict, only bookmark flag is forced true).

Query params
  • opportunity_id (required)
Example response
{ "message": "Grant bookmarked successfully" }
GET/api/user_activity/unbookmark_grant

Removes the bookmark for the session user on an existing user_grant_activity row: sets is_bookmarked = FALSE and unbookmarked = TRUE so you can query “previously saved then removed” grants separately from never-touched rows.

Query params
  • opportunity_id (required)
Notes
  • Requires a row to already exist for that (user_id, opportunity_id) (typically after a bookmark or status update). No insert is performed here.
  • The user_grant_activity table must include an unbookmarked boolean column for this update and for get_unbookmarked_grants.
Example response
{ "message": "Grant unbookmarked successfully" }

Maintenance / data reset

GET / POST/api/db_migration/add_unbookmarked_grants

Idempotent schema tweak: adds unbookmarked on user_grant_activity if missing.

GET / POST/api/db_migration/normalize_grant_dates

Backfills posted_date, close_date, and last_updated_date to ISO YYYY-MM-DD using the same parser as ingestion (normalize_grant_date). Run once if older rows still have spelled-out months (e.g. September 15, 2024), which sort incorrectly as plain text.

Response
{ "message": "Grant dates normalized to YYYY-MM-DD where parseable", "rows_updated": 0 }
GET / POST/api/db_migration/update_grant_gov_url

Backfills grants.grant_gov_url for every row using compute_grant_public_url: copies the funding description link_url when present; otherwise sets grant_gov_url to null (same as ingestion).

Response
{ "message": "grant_gov_url refreshed …", "rows_updated": 0 }
GET / POST/api/db_migration/reset_tables

Destructive. Drops all tables in the public schema (Postgres) or all user tables (SQLite). Use only in dev or with a full backup.

Response

{ "message": "Tables reset successfully (N dropped)" } on success.

GET/api/reset_oei_data

Deletes grants with opportunity_source = 'wi_psc_oei' and related rows in dependent tables (grant_snapshots, grant_alerts, grant_tags, tribal_eligibility, user_grant_activity, grant_checklist_items).

Response
{
  "message": "WI PSC OEI grants reset successfully",
  "deleted_grant_rows": 0,
  "cleared_opportunity_ids": 0
}

HTML (non-JSON)

The dashboard serves pages under /dashboard, /grants, /alerts, /portal, and this page at /api-docs. Those return HTML, not JSON.

Error format: endpoints generally return HTTP 500 with JSON like { "message": "Error ...: <details>" } when exceptions occur.
